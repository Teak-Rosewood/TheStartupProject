# Project review, October 2026

A review of the whole kit as of commit `45af245`, assuming phases 1–7 of the [roadmap](roadmap.md) finish as planned. Findings are ordered by how much they hurt if left alone: **blockers** stop a real launch, **gaps** are things a startup will need within its first year, **improvements** make the kit better to build on. Each has a suggested fix and the roadmap phase it lands in.

What is already strong, and should stay that way: one `EnvConfig` driving the whole AWS stack with cdk-nag in tests; idle cost near $22–45/month with every scale step a config switch; backups that are restored monthly in CI; consent, export, deletion and audit built in from the start; India-specific payments and GST; and a multi-provider AI client with a verified catalog. 339 tests across the Python packages, plus web and landing tests.

## Blockers

### B1 Deploy and security workflows never run
`.github/workflows/deploy.yml` and `.github/workflows/security.yml` trigger on pushes to `main`, but the repository's only branch is `master`. Nothing deploys on merge, and the security scan only runs on pull requests and its weekly schedule. `docs/aws/11-multi-env.md` also assumes `main`.
**Fix:** rename the default branch to `main` (preferred; the docs already say `main`) or change both triggers to `master`. Before phase 8.

### B2 Docs the code points to do not exist
`python/packages/infra/src/tsp/infra/config.py` and the `flags`, `storage` and `metering` READMEs link to `docs/modules/product-ops.md` and `docs/aws/16-ai-gateway.md`, which are not written yet. `make docs-check` does not catch this because it only checks links inside Markdown under `docs/` and the repo root.
**Fix:** write both pages as the last step of phase 7, and extend `docs/check_links.py` to scan `docs/...md` references in package READMEs and Python sources.

### B3 Status pages disagree with the code
- `README.md` lists payments as "planned" and the AWS stack as "designed", and only five modules, while the code has about twenty.
- `docs/startup/gaps.md` says `tsp.ai` is not mounted and there is no per-customer quota or usage billing; `python/apps/api/src/tsp_api/ai.py` now does exactly that with credits, plan rate limits and a kill switch. It also says there is no frontend beyond a placeholder, but `js/packages/web-app` exists.
- `CHANGELOG.md` stops at the AWS stack and legal docs.
**Fix:** refresh all three when phase 7 closes; add a CI check that every package under `python/packages` appears in `docs/aws/13-library-modules.md`. Before phase 8.

### B4 Never deployed
Every cost, runbook and alarm is unverified against a real account (stated in `docs/aws/README.md`). This is the largest single risk to the "cheap and safe" promise.
**Fix:** a first deploy to a throwaway account, run each runbook once, record real costs in the AWS README, then delete. Phase 9.

### B5 Production log retention
Default CloudWatch retention is 14 days; CERT-In directions expect 180 days for security-relevant logs (marked verify in the docs). It is configurable (`log_retention_days`) but `config/prod.py` keeps the default.
**Fix:** set 180 in `prod.py`, or export logs to an S3 bucket in `ap-south-1` with a lifecycle rule, which is cheaper. Before phase 8.

## Gaps

### AI and data
| Gap | Why it matters | Fix | Phase |
|---|---|---|---|
| No embeddings in `tsp.ai` (only an abstract `embedding()` in `providers/base.py`) and no `/v1/embeddings` in the gateway | blocks RAG, semantic search, dedup, recommendations | [phase 8.1](roadmap.md#81-embeddings-in-tspai) | 8 |
| No vector store | same | [docs/aws/17-vector-search.md](aws/17-vector-search.md), new `tsp.vector` | 8 |
| No full-text search (no `tsvector` or `pg_trgm` anywhere) | every product needs a search box; also half of hybrid search | add in `tsp.vector` and reuse for other tables | 8 / 11 |
| Streamed AI responses are billed from a token *estimate* | over- or under-charging customers on long streams | request `stream_options.include_usage` where providers support it, fall back to estimates | 10 |
| No default content moderation (`AiGateway.moderate` is an empty hook) | abuse of your API keys becomes your legal problem ([acceptable use](legal/acceptable-use.md)) | ship one moderation implementation (provider moderation endpoint or a small classifier) behind a flag | 10 |
| No LLM evaluation or prompt versioning | silent quality drops when the router changes models | golden-set evals in a nightly job; record prompt version with each usage row | 8.8 / 10 |
| No semantic cache | repeated questions cost full price | cache by embedding similarity in Valkey, per organization | 10 |
| No data warehouse or BI (already noted in [gaps](startup/gaps.md)) | metrics stay in admin pages | nightly export of events and usage to S3 (Parquet) queried with Athena: pennies at this scale | 11 |

### Reliability and operations
| Gap | Fix | Phase |
|---|---|---|
| No dev environment; every change is tested only in CI then prod | build the `DevStage` described in [11 Multi-env](aws/11-multi-env.md) once revenue allows (~$20/month) | 9 |

| No cross-region backup copy or DR runbook | copy pgBackRest and DynamoDB backups to a second region (e.g. `ap-south-2` Hyderabad, keeps data in India) and rehearse a region loss yearly | 12 |
| No public status page | a hosted status page, linked from the app footer; [support guide](startup/06-support-and-ops.md) already expects one | 11 |

### Security and compliance
| Gap | Fix | Phase |
|---|---|---|
| Tenant isolation is application-level only (every query filters `org_id`; no Postgres row-level security) | enable RLS with `SET app.org_id` per request on tenant tables, starting with vectors and uploads; one missed `WHERE` then cannot leak data | 8 / 12 |
| WAF is left to the CloudFront flat-rate plan by design (`nag.py` suppresses the check), so nothing in code sets rules | once on a paid plan, document which managed rule groups and which rate-based rule on `/api/*` to turn on, and add it to the launch checklist | 9 |
| No container image signing or SBOM | generate an SBOM in CI and sign images; keep for enterprise questionnaires | 12 |
| No SSO for customer organizations (SAML/OIDC) | Cognito supports per-org identity providers; a common enterprise ask | 12 |
| No SOC 2 / ISO 27001 evidence (already noted) | map existing controls (audit log, backups drill, access reviews) to a control list early; costs little now, a lot later | 12 |
| No DAST or penetration-test plan | OWASP ZAP baseline scan against the dev environment in CI; annual external test | 10 |
| E-invoicing (IRN) not generated (already noted) | needed once GST turnover passes the mandatory threshold; integrate a GSP API | 12 |

## Improvements to how the kit is built

- **One status source.** Generate the module table in `README.md`, `docs/aws/13-library-modules.md` and `docs/startup/gaps.md` from package metadata so they cannot drift again (B3).
- **ADRs for the big calls.** Only one ADR exists. Record the ones already made (multi-provider AI over Bedrock-only, credits over per-token invoices, India-first payments) and the new one: [pgvector first](aws/17-vector-search.md#decision).
- **A "use the kit for a new startup" guide.** Which modules to delete, what to rename (`tsp-` prefixes, `example.com`), which `CHANGE` values to set, and the order to switch things on. This is the first thing a founder using the kit will need.
- **Per-organization cost attribution.** `tsp.metering` records usage; add AWS cost-allocation tags and a monthly report of cost versus revenue per organization, so pricing decisions use real margins.
- **Sample app.** `python/apps/api` uses "notes" as the demo entity; a slightly richer sample (documents with search once phase 8 lands) would show how modules compose.
