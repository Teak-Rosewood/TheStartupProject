# Languages (`tsp.i18n`)

Serve content in several languages, with the right language per request and search that works in Hindi. Package: `python/packages/i18n`. Hindi search lives in [vector search](vector.md#languages).

## Messages
`Catalog(*dirs, default="en")` reads gettext `.po` files at `<dir>/<lang>/messages.po` directly with Babel (no compile step). English and Hindi catalogs for the newsletter, share cards and the AI-image label ship with the package; your directories are loaded after them and override them. Messages use `{name}` placeholders.

```python
from tsp.i18n import Catalog
cat = Catalog("locales")                       # your app's catalogs
cat.t("newsletter.subject", "hi", count=3)     # "इस सप्ताह: 3 नई रेसिपी"
cat.missing("hi")                              # keys English has and Hindi lacks
```
A missing key falls back to the default language, then to the key itself, and is logged once. A bad placeholder never raises.

## Choosing the language
Order: **URL prefix** (`/hi/recipes/x`), then the **`lang` cookie**, then **`Accept-Language`** (q-values respected, region tags reduced to the base language), then the default. `negotiate(path, supported, default, cookie=, accept_language=)` returns the language, where it came from and the path without the prefix. In FastAPI use `Depends(make_get_lang(["en", "hi"], "en"))`.

Pages that vary by language should send `Vary: Accept-Language, Cookie` when they pick a language without a prefix, and every language version should live at its own prefixed URL so search engines can index it.

## hreflang
`hreflang_links(base_url, path, languages, default, available=None)` returns the `<link rel="alternate" hreflang>` entries for a page, including `x-default`. Pass `available` so a page lists only the languages that exist. `missing_languages(configured, available)` is the check a publishing flow uses to decide whether every variant is ready.
